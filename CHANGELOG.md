# Changelog

## PA.0.6.0 - 2026-11-06

### Package 06 closeout — Native experience, presentation-only Flare and explicit export

- **Native input → generate → result journey.** The app is now a three-tab experience: Dashboard (the existing status surface), **Create** (the new journey), and **Records** (CRUD). The Create tab hosts a `SigilProfileFormView` that binds to a `SigilProfileDraft` (distinct from the canonical `SigilProfileInput`) with field-level errors. A `SigilDraftPromoter` is the single domain-boundary point that validates and promotes a draft to a canonical input (required: name, birth date, birth city; all other fields optional with unknown as a legitimate state). Submit runs the **real** pipeline (`SigilVisibleGlyphService` + `SigilPersonalCodexService`) off the main actor through a `SigilGenerationJourneyViewModel` state machine (idle/loading/success/failure/cancelled) with a monotonically-increasing `requestSequence` that drops out-of-order completions and supersedes in-flight requests on a new tap.
- **Results and readable PersonalCodex.** `SigilResultView` presents the canonical glyph (rendered from SVG via `Canvas`), the deterministic celestial name, a concise provenance summary, readable PersonalCodex sections, and an advanced disclosure for raw geometry. Unavailable data is shown honestly, not hidden behind decorative content.
- **Protected local records (real secure store).** `SigilRecordsStore` is an actor that wraps the real `SigilSecurePersistenceService` (AES-GCM, keys in the Keychain, ciphertext in a local directory) with `upsert`/`open`/`delete`/`list`. The records tab shows saved records, supports explicit+cancellable delete, and refreshes on pull. The app constructs the **real** `SigilPersonalCodexService` (canon loader) and `SigilSecurePersistenceService` (KeychainKeyStore), not placeholders. The persistence service gained async `delete` and `list`.
- **Flare is a presentation-only editor.** The Flare editor offers a small, fixed set of approved palettes (canonical/aurora/ember/frost/midnight) and backgrounds (transparent/light/dark) plus a glow slider, with a side-by-side canonical-vs-styled preview and return-to-canonical. Flare never modifies the canonical identity, vector paths, or digests (verified by tests across 3 styles). Save commits the style to the records store.
- **User-selected export/share.** Five bounded formats, each a distinct artifact the user explicitly selects: canonical SVG, styled (Flare) SVG, PersonalCodex JSON, PersonalCodex Markdown, and a redacted diagnostic JSON (record type, outcome, schema, digest only — no personal data). The export writes a temp file atomically and presents a native `ShareLink`; the temp file is cleaned up on dismiss. No automatic diagnostic/profile attachment.
- **Native functional integration tests.** `JourneyIntegrationTests` runs the real service integration (not mocks) through create → generate → read record → save → reopen → Flare → export with a synthetic fixture, covering save/reopen round-trip integrity, the Flare presentation-only guarantee, out-of-order completion drop, empty-draft validation, and 10 concurrent writes serialized by the records store.
- **Verification:** `swift build` clean; `swift test` 136/136 (up from 111 at the Package 05 baseline). No new third-party runtime dependencies (SwiftUI/Foundation/CryptoKit/UniformTypeIdentifiers system frameworks only). No analytics/backend/upload; all records local-only, encrypted-at-rest.
- See `docs/design/native-experience-export.md` for the full design record.

## PA.0.5.0 - 2026-11-06

### Package 05 closeout — ASH-derived canonical glyph

- The visible glyph is now the **canonical ASH branch geometry** (ASH-TRACE F-07): the profile's decoded ASH state is resolved to a branch message through a product-owned **reference-codeword to APS-codeword message seam**, and the visible vector paths are a deterministic, source-backed branch fan projected from the canonical topology into the 100x100 viewBox. The digest-parameterized geometry is gone; a missing message or an out-of-budget fan fails closed (the quality gate rejects it) rather than fabricating geometry.
- Shipped the canonical branch topology as an integrity-verified resource in `RFSigilVisibleGlyph` (`Resources/ash/branch-topology.json`, SHA-256 `e114168b…d3748c`, 121 nodes / 81 leaves, depth 0-4 full ternary tree) with a product-owned provenance manifest (`ash/ash-manifest.json`). A new `SigilBranchTopologyLoader` re-hashes the shipped file against the manifest and fails closed on any mismatch, decodes it into typed models, and structurally validates the tree (node/leaf counts, a single root, parent links, finite coordinates, `state == codeword`, 16 well-formed messages and 16 codewords). Generation throws `branchTopologyUnavailable` rather than substituting a fabricated renderer.
- The 16 branch codewords form a `[9,4,4]` code. The message seam is the unique mapping that carries the reference codeword set exactly onto the product's APS-native `[9,4,4]` set (verified: a 16<->16 bijection, every derived word has bit b8 == 0, minimum distance 4). It is derived at load from the resource and the product codeword set and pinned by test; it is distinct from the product's `b6 <-> b7` coordinate adapter.
- Selection is deterministic and source-backed: per message, the smallest leaf fan within the presentation budget (10...14 strokes) whose **real** segment crossings are within the quality limit (<= 3). Sparse channels are completed deterministically from adjacent messages, shifted by the candidate index so collision resolution changes the geometry. The major-crossing count is now a **real, recomputed** proper-interior intersection count over the rendered geometry (replacing a synthetic stand-in; a caller-provided count is not verification). A geometry-only collision signature (a hash of the quantized segment set, independent of the profile digest) is recorded for data-quality cross-profile identity, while the candidate loop still advances on the profile-linked visible signature.
- Completed the Package 04-deferred PersonalCodex Sigil Reading: it is now complete and records a one-way provenance link to the canonical geometry digest **and** to the geometry-only identity of the selected visible branch geometry (the picture the glyph renders). The link is one-way: the glyph does not hash back to the PersonalCodex, and the acyclic record digest is unchanged in construction. No new target dependency was introduced.
- Corrected a stale identity test: the master number is annotation-only (preserved in the numerology record and reduction provenance, not driving a visible stroke) — the branch-derived glyph has no numerology accent path, which matches the test's own name better than the prior behavior.
- Tests: 6 new `BranchGlyphTests` (seam 16<->16 bijection onto the APS `[9,4,4]` set; deterministic message-driven projection; real crossing verification; geometry-only collision signature order-invariance, distinction, and a cross-profile same-geometry pair; loader fail-closed on a tampered resource SHA; shipped-topology structural well-formedness), for 111 tests total, 0 failures.
- Version/build: `PA.0.4.0` -> `PA.0.5.0` (feature advance for the ASH-derived canonical glyph); Apple build identity 5 -> 6. `VERSION` is the source of truth; `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` are aligned in `project.yml` and the regenerated `Sigil.xcodeproj`. See [docs/verification.md](docs/verification.md) and [docs/design/ash-derived-glyph.md](design/ash-derived-glyph.md).
