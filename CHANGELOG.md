# Changelog

## PA.0.3.0 - 2026-11-05

### Package 03 closeout — artifact health, privacy, and encrypted local persistence

- Added a product-owned, non-destructive artifact-health validator in `RFSigilAeostaraIntegration` (`SigilArtifactHealthValidator.swift`) that applies the retained Aeostara base lifecycle to the real artifact: diagnose, classify, determine recoverability, policy gate, non-destructive in-memory recovery, verify, and monotonic containment / safe-halt. It is fail-closed and pure, and recovers only metadata actually derivable from intact authoritative content (a visible-side defect is recoverable-derivable only when the authoritative hidden half is internally intact: schema, algorithm identity, identity, internal digest, and topology all pass). It never fabricates values; regeneration is planned-not-executed under the fail-closed health policy. All five `AeostaraArtifactFailureKind` cases are covered (corrupt JSON via `validate(data:)`, unknown schema, missing required data, invalid topology, and non-recoverable failure). 10 new `ArtifactHealthTests`.
- Added public `canonicalGeometryDigest(for:)` to `SigilVisibleGlyphService` (reusing the private canonical encoder) so the validator can independently recompute and verify the recorded digest; the gateway now exposes `validate(artifact:)` and `validate(data:)` and `RFSigilAeostaraIntegration` depends on `RFSigilVisibleGlyph` (acyclic) so it can inspect the real artifact. The pre-existing status surface and fail-closed stub are retained.
- Implemented real, local-only encrypted persistence in `RFSigilPrivacySecurity` (`SigilSecureRecordStore.swift`, `SigilEncryptionKeyStore.swift`, `SigilSecureStorageTypes.swift`): a serialized actor owning transactional save/load/delete under a single partition; a versioned `SigilSecureEnvelope` whose `ciphertext` holds the AES-GCM combined buffer (nonce || ciphertext || tag) sealed with CryptoKit `AES.GCM.seal`; a `SigilEncryptionKeyProviding` protocol with a production `SigilKeychainKeyStore` (`kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly`) and a `SigilInMemoryKeyStore` for host tests; keys stored separately from ciphertext and never beside it; atomic temp-file + `replaceItemAt` so a failed or interrupted write preserves the last-verified record; integrity via a SHA-256 record digest on read (a hash, explicitly not the encryption). Storage identity (`SigilRecordIdentity` / `SigilRecordType`, including `personalCodex`) is deliberately separate from mathematical identity. No CloudKit, sync service, or upload. 14 new `SecureStorageTests` (round-trip, no-plaintext-leak, keys-not-beside-ciphertext, atomic update, failed-replacement preserves last-verified, wrong/missing key, tampered ciphertext, corrupt record, unsupported version, not found, list/delete, concurrent writes, storage-versus-math identity).
- Integrated health, storage, and diagnostics into the runtime (`SigilSecurePersistenceService.swift`): a truthful facade whose `save` returns a `SigilSaveOutcome` — a failed save is reported as `success == false` with a `failureCategory` and the record count is left unchanged, never reported as success. Diagnostics are redacted by construction: only record type, failure category, and record count are handed to the collector (never the record payload, key material, storage path, or record identifier), using the tracked operation `sigil.persistence.save`. A pure, I/O-free `readiness()` drives a new `secure-persistence` dashboard card. 4 new `SecurePersistenceIntegrationTests` (a failed save is a `.writeFailed` failure and not counted; a save/load round-trip; the dashboard card is present and not a sensitive path; and a capturing collector proves no payload/key/path/identifier leak on the success and failure paths).
- Version/build: `PA.0.2.0` -> `PA.0.3.0` (feature advance for new user/runtime capability: real local encrypted persistence and artifact-health validation now ship in the runtime); Apple build identity 3 -> 4. `VERSION` is the source of truth; `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` are aligned in `project.yml`, and `xcodegen` regenerated `Sigil.xcodeproj`, adding the five new Slice 03 source files to their framework targets and updating the app marketing/build version. `Info.plist` continues to use build settings.
- Verification (fresh 2026-11-05): `swift build` with 0 errors and 0 warnings; `swift test` 76 tests, 0 failures, 0 unexpected (48 from Package 02 plus 10 `ArtifactHealthTests`, 14 `SecureStorageTests`, and 4 `SecurePersistenceIntegrationTests`); the strict project guardrail wrapper (strict validator + `swift test --parallel` 76/0 + `xcodebuild -list`) passed; `git diff --check` clean. The full iOS-simulator `xcodebuild` test was not re-run in this session; the guardrail `xcodebuild -list` confirms the regenerated project is well-formed and target membership is complete. See `docs/verification.md`.
- Device/simulator keychain data-protection behavior remains an owner qualification: the host tests prove the native crypto, storage, and atomic-replacement logic with an injected key, not the OS keychain protection. No new third-party runtime dependency (CryptoKit/Security are system frameworks), no schema or test removal; the Forsetti pin and schema/algorithm versions are unchanged. The additional personal-data embedding requirement remains removed, not deferred.

## PA.0.2.0 - 2026-11-04

### Package 02 closeout — identity pipeline: standard numerology and ASH/APS realization

- Implemented the retained input model and local validation in `RFSigilVisibleGlyph` (`SigilIdentityModels.swift`): a timezone-free civil date with a pure-Gregorian weekday (no host clock, timezone, or locale); typed birth order validated as `1 <= ordinal <= total`; fixed hair/eye category tables with a deterministic alias fold; canonical heritage family groups (germanic, celtic, slavic, mixed); the product four-bucket birth-time annotation; and location-precision recording. `present`/`unknown`/`unsupported` field states are explicit, with unknown distinct from unsupported and no fabricated substitute for an unavailable value.
- Made the standard numerology bridge explicit and source-backed (`SigilNumerologyEngine.swift`): the exact conventional Pythagorean letter table, an NFC/NFD base-letter normalization that folds the eszett to `s`, Y always a vowel, the full-date life path (eight digits of `YYYYMMDD`), and the expression/soul-urge/personality roots. Roots are always reduced to 1-9; 11/22/33 are preserved as annotations with the intermediate reduction chains recorded for provenance. Fixed a defect where the preserved master numbers were read from the empty output accumulator and were therefore always empty; they now capture any 11/22/33 met along a reduction chain.
- Resolved the applicable ASH state through the governing contracts (`SigilAshIdentity.swift`): a finite nine-bit `F2^9` state in the APS native convention (zero-based `b0..b8`, where `b8` is the canonical convention rather than a derived value), stored packed so arbitrary non-codeword states are never written as nine-bit literals; the exact 16-member `[9,4,4]` codeword set (`b8 = 0` in every member) as a product-owned constant mirroring the pinned APS canonical reference and the repository guardrail; orbit enumeration under XOR-by-codeword (16-member cosets, 32 orbits over the 512 states); codeword/orbit-member classification; and nearest-codeword decoding with radius and ambiguity that never mutates the input state. `SigilAshStateRecord` replaces the digest-substitute stabilized-state semantics and carries `algorithmIdentity = sigil-ash-state.v1`.
- Added the named, versioned profile-to-state seam `SigilProfileAdapterV1` (`sigil-profile-adapter.v1`): one parity rule per coordinate over the normalized numerology and input signals (no digest bytes enter the semantic path), with fail-closed behavior when an identity-core signal (date, name, birth order, or heritage) is unavailable. The wolf coordinate always has the generator's documented default-modifier path and is therefore never a hard failure. The final-two-coordinate swap (`b6 <-> b7`) coordinate adapter is an involution over all 512 states that commutes with XOR-by-codeword, verified exhaustively in tests.
- Wolf balance uses the celestial generator's explicit white/dark modifier tables for hair, eyes, and time bucket (cited supplied-generator behavior, versioned with the generator reference) with the retained 0.12 balanced band; the generator's five-bucket time scheme feeds the wolf contribution while the product's four-bucket annotation remains a separate recorded signal. The dominant plane is the life-path root (P1-P9).
- The hidden canonical geometry now carries the real source-backed ASH state, numerology vector, plane attunement vector, wolf balance, ancestry weights, and celestial class basis under `algorithmIdentity = sigil-identity-pipeline.v1` (schema `rf.hidden_geometry.v1` unchanged). The visible path synthesis retains the existing deterministic bounded renderer, which is labeled the temporary bounded renderer; Package 05 replaces it with canonical branch geometry.
- Diagnostic instrumentation: the visible-glyph service instruments the identity resolution as the tracked operation `sigil.identity.resolve` through the existing `SigilDiagnosticCollector` contract (optional; no-op when unset) and records the state/orbit decision, fail-closed warnings for missing identity-core signals, and a supplied-versus-derived weekday mismatch warning. It never records personal raw values; see `docs/diagnostics.md`.
- Tests: 15 new `IdentityPipelineTests` (independently computed spec fixtures, letter normalization and numerology roots, weekday reduction, master-number preservation, wolf categories, fail-closed input classes, the 512/16 codeword and coordinate-adapter invariants, and the ASH state record) in addition to the retained 6 visible-glyph generation tests; 48 tests total, 0 failures, on both macOS (SwiftPM) and the iOS simulator.
- Version/build: `PA.0.1.1` -> `PA.0.2.0` (feature advance for new user/runtime capability); Apple build identity 2 -> 3. `VERSION` is the source of truth; `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` are aligned in `project.yml` and the regenerated `Sigil.xcodeproj`; `Info.plist` continues to use build settings. A previously missing `RFSigilDiagnostics` dependency edge on the `RFSigilVisibleGlyph` Xcode target was added to `project.yml` so the iOS target resolves (the SwiftPM target already carried it).
- Verification (fresh 2026-11-04): 48/48 Swift package tests; 48/48 iOS-simulator tests; Debug iOS-simulator build compiled with no project-code warnings in Package 02 sources (one pre-existing test-file warning in the Package 01 `DiagnosticCaptureTests`); strict project guardrails, version guard, attribution guard, and 17 guard unit tests passed; built `SigilApp.app/Info.plist` reports `CFBundleShortVersionString = PA.0.2.0`, `CFBundleVersion = 3`.
